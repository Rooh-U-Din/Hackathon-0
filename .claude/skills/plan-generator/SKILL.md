# Plan Generator Skill

Create detailed Plan.md files for multi-step tasks using Claude's reasoning capabilities.

## What this skill does

This skill analyzes tasks and:
1. Identifies multi-step tasks requiring planning
2. Uses Claude Code to reason through the approach
3. Creates structured Plan.md files in /Plans folder
4. Breaks down complex tasks into actionable steps
5. Identifies dependencies and blockers
6. Estimates effort and resources needed

## When to use

Run this skill when:
- A task in /Needs_Action is complex (3+ steps)
- You need to break down a large project
- Multiple dependencies exist
- Task requires coordination across domains
- Uncertainty about best approach

## Usage

```bash
# Analyze all tasks and create plans for complex ones
/plan-generator

# Create plan for specific task
/plan-generator --task-file "ACTION_client_project.md"

# Set complexity threshold
/plan-generator --complexity-threshold 5
```

## Workflow

1. **Scan Tasks:**
   - Read all files in /Needs_Action
   - Analyze task complexity
   - Identify multi-step tasks

2. **Analyze with Claude:**
   - Read Company_Handbook.md for context
   - Read Business_Goals.md for priorities
   - Reason through best approach
   - Consider dependencies and risks

3. **Generate Plan:**
   - Break into discrete steps
   - Assign priorities
   - Identify blockers
   - Estimate timeline
   - Note approval requirements

4. **Create Plan File:**
   - Save to /Plans folder
   - Link to original task
   - Update task status
   - Log activity

## Plan File Format

```markdown
---
type: plan
task_id: ACTION_client_project_20260227
created: 2026-02-27T10:00:00Z
priority: high
status: in_progress
estimated_duration: 3 days
requires_approval: true
---

# Plan: Client Project Implementation

## Objective
[Clear statement of what needs to be accomplished]

## Context
- Original task: /Needs_Action/ACTION_client_project.md
- Business goal: Deliver project on time
- Constraints: Budget $5000, Deadline March 1
- Dependencies: Client approval, API access

## Approach Analysis

### Option 1: Incremental Delivery (Recommended)
**Pros:**
- Lower risk
- Early feedback
- Flexible timeline

**Cons:**
- More coordination
- Potential rework

### Option 2: Big Bang Delivery
**Pros:**
- Single delivery
- Less coordination

**Cons:**
- Higher risk
- Late feedback

**Decision:** Option 1 - Incremental Delivery

## Step-by-Step Plan

### Phase 1: Setup (Day 1)
- [ ] Step 1.1: Review requirements with client
  - Priority: High
  - Requires approval: Yes
  - Estimated time: 2 hours
  - Blocker: None

- [ ] Step 1.2: Set up development environment
  - Priority: High
  - Requires approval: No
  - Estimated time: 1 hour
  - Blocker: None

### Phase 2: Implementation (Day 2-3)
- [ ] Step 2.1: Build core functionality
  - Priority: High
  - Requires approval: No
  - Estimated time: 8 hours
  - Blocker: Step 1.2

- [ ] Step 2.2: Integrate with client API
  - Priority: High
  - Requires approval: Yes (API credentials)
  - Estimated time: 4 hours
  - Blocker: Step 2.1

### Phase 3: Testing & Delivery (Day 3)
- [ ] Step 3.1: Test all functionality
  - Priority: High
  - Requires approval: No
  - Estimated time: 3 hours
  - Blocker: Step 2.2

- [ ] Step 3.2: Deploy to production
  - Priority: High
  - Requires approval: Yes
  - Estimated time: 1 hour
  - Blocker: Step 3.1
```

## Complexity Detection

**Simple Task (No plan needed):**
- Single action
- No dependencies
- Clear execution path
- < 1 hour

**Medium Complexity (Plan recommended):**
- 2-3 steps
- Some dependencies
- Multiple approaches possible
- 1-4 hours

**High Complexity (Plan required):**
- 4+ steps
- Multiple dependencies
- Significant uncertainty
- > 4 hours
- Requires coordination

## Integration with Workflow

1. **Task arrives** in /Needs_Action
2. **Plan Generator** analyzes complexity
3. **If complex:** Creates plan in /Plans
4. **Claude Code** executes plan step-by-step
5. **Human approves** at approval points
6. **Task moves** to /Done when complete

## Configuration

Edit `Company_Handbook.md` to customize:
- Complexity thresholds
- Planning templates
- Approval requirements
- Risk tolerance

## Benefits

- **Clarity:** Clear roadmap for complex tasks
- **Efficiency:** Avoid rework and confusion
- **Accountability:** Track progress step-by-step
- **Risk Management:** Identify issues early
- **Communication:** Share plan with stakeholders

## Troubleshooting

**No plans generated:**
- Check complexity threshold
- Verify tasks in /Needs_Action
- Review task descriptions

**Plans too detailed:**
- Increase complexity threshold
- Adjust planning template
- Focus on high-level steps

**Plans not followed:**
- Ensure Claude Code reads plan
- Check approval workflow
- Update task status regularly
